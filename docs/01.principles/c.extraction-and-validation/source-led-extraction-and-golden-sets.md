# Source-led extraction and golden sets

> **Status:** AGREED
> **Scope:** extraction, Bronze, validation

## Principle

Each PDF receives an LLM-led source review and a bespoke Python extractor. Independently human- or LLM-authored golden sets specify the required values and metadata; the extractor is iterated against them. Golden sets are living specifications.

## Rationale

PDF layouts and definitions vary. A parser can produce plausible numbers while missing a row, misreading a period or borrowing an inapplicable definition. Expected results generated by that same parser cannot independently establish correctness.

## Implications

- Review relevant tables, surrounding context, notes and glossaries. Inspect rendered pages when text extraction loses meaningful layout or content.
- Include all selected columns, bands, aggregates and applicable qualifications in the golden scope. Structural and semantic metadata receive the same scrutiny as values.
- Humans or LLMs may extend or correct expectations from source evidence. Ordinary tests use saved versions without LLM calls.
- These development tests do not run implicitly in the processing workflow. [Validation is a separate process](validation-is-a-separate-process.md), and its requirements remain undefined.
- Keep tests under `tests/bronze/<reporting-jurisdiction>/<org>/<document-date>/<extraction-id>/`, mirroring the extractor and Bronze hierarchy.
- Report mismatches at dataset, row and field level, including metadata mismatches. Dropped fields cannot silently pass through an older comparator.
- Extend shared dataclasses and helpers from demonstrated requirements across real extractions. Preserve coverage of previously selected datasets when adding domains or jurisdictions.
- Separate faithful extraction, structural Silver conformance and task-specific analytical suitability. Passing extraction checks does not resolve unknown metric semantics, but partial semantic knowledge does not prevent capture or publication with appropriate tags. Analysis may use explicit assumptions and approximations; perfect accounting is not an acceptance criterion.

## Example

A fixture with correct EAD amounts but an incorrect default category or an unsupported PD-weighting convention is incorrect. An omitted BNZ CR9 interval must not be filled with zeros merely to match another bank's band structure.
